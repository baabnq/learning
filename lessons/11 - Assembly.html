Lesson 11 - Assembly

Baabnq compiles down to S1Asm (S1monsAssembly, very creative name, i know, but i came up with it like 6 years ago, so cut me some slack). This is relevant because it means that all inline assembler written in baabnq is S1Asm.
Inline assembler in baabnq is done with the asm command. Consider the following example: 

asm 'set 123';
asm 'sRD 0';
asm 'out 0';
asm 'brk';

The above example will print 123, but it's functioning isn't relevant for now.
S1Asm always targets the S1AsmVM, which is a minimal 16-bit virtual machine. It will be detailed in the following. For some example snippets, refer to this. (Which is recommend you do, because i spent way too long on them).

Specifications

- fully 16 bit
    -> 16 bit registers
    -> 65k data memory
    -> 65k program memory 
    -> 65k stack

- 2 general purpose registers
    -> "Acc" = accumulator
    -> "Reg" = (aux) register

- 2 (nameless) special purpose registers
    -> stack pointer
    -> program pointer/counter

- vm managed heap in upper 32k of data memory
    -> no runtime necessary because vm does alloc/dealloc

( - baabnq stores dynamic chunks on the heap)
( - baabnq stores static  chunks and variables in the rest)

This diagram only contains core components and omits more complicated parts, like the heap manager, for sake of readability.

Instruction Set

Some instructions take an attribute, which is denoted "attr".

Mnemonic Meaning Pseudocode Description
"set" SET reg = attr Load attribute as literal into reg
"add" ADD acc += reg Add reg to acc
"sub" SUBtract acc -= reg Subtract reg from acc
"shg" SHift Great acc *= 2 Shift acc in MSb direction
"shs" SHift Small acc /= 2 Shift acc in LSb direction
"lor" Logical OR acc |= reg Take bitwise OR of acc and reg, write back to acc
"and" AND acc &= reg Take bitwise AND of acc and reg, write back to acc
"xor" eXclusive OR acc ^= reg Take bitwise XOR of acc and reg, write back to acc
"not" NOT acc ~= acc Take bitwise NOT of acc, write back to acc
"lDA" Load Data Acc acc = mem[attr] Load memory at addr into acc
"lDR" Load Data Reg reg = mem[attr] Load memory at addr into reg
"sAD" Save Acc Data mem[attr] = acc Save acc into memory at addr
"sRD" Save Reg Data mem[attr] = reg Sava reg into memory at addr
"lPA" Load Pointer Acc acc = mem[mem[attr]] Load memory at pointer at addr into acc
"lPR" Load Pointer Reg reg = mem[mem[attr]] Load memory at pointer at addr into reg
"sAP" Save Acc Pointer mem[mem[attr]] = acc Save acc into memory at pointer at addr
"sRP" Save Reg Pointer mem[mem[attr]] = reg Save reg into memory at pointer at addr
"out" OUTput out(mem[attr]) Write memory at attr to stdout (implementation dependent)
"inp" INPut mem[attr] = in() Read stdin into memory at attr (implementation dependent)
"lab" LABel LUT[attr] = PC Define the label of name given by attr
"got" GOTo PC = LUT[attr] Jump to label given by attr
"jm0" JuMp if 0 if (acc == 0) PC = LUT[attr] Jump to label given by attr if acc is zero
"jmA" JuMp if Acc is reg if (acc == 0) PC = LUT[attr] Jump to label given by attr if acc is reg
"jmG" JuMp if Greater if (acc > reg) PC = LUT[attr] Jump to label given by attr if acc is greater than reg
"jmL" JuMp if Lesser if (acc < reg) PC = LUT[attr] Jump to label given by attr if acc is lesser than reg
"jmS" JuMp Subroutine stack.push(PC+1); PC = LUT[attr] Call subroutine giben by attr
"ret" RETurn PC = stack.pop() Return from subroutine
"pha" PusH Acc stack.push(acc) Push from acc to stack
"pla" PuLl Acc acc = stack.pop() Pop from stack to acc
"brk" BReaK exit() Halt execution
"clr" CLeaR acc = reg = 0 Clear acc and reg, setting them to zero
"putstr" PUT STRing putchar(acc) Write acc to stdout as a unicode character
"ahm" Allocate Heap Memory acc = malloc(reg) Allocate memory on the heap
"fhm" Free Heap Memory free(acc) Free memory on the heap

Annotations

  • In the standard implementation of the VM, the "out" and "inp" instructions write/read a decimal number from/to stdio respectively.
  • The "lab" instruction is the only preprocessed instruction.
  • The "fhm" instruction requires reg to contain the size of the memory region to be freed for verification purposes.
